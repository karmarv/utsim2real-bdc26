The task, decoded

Four mandatory steps, one hard rule

You never train on real labels. You synthesize data, learn from it, and are judged on a real sensor you have only seen unlabeled. Everything in this guide serves those four steps.

The rule that shapes everything: the detector must be trained on synthetic data only. A forbidden_frames.txt lists 100 frames per track (50 test + 50 realism reference) you must never touch. Confirm whether even unlabeled real frames may be used for self-training: it decides whether an entire class of adaptation methods is legal.
Where points come from

The score is 60% detection, 40% realism

Both halves are normalized with endpoints shipped in config.json, and the exact scorer (local_eval.py) ships in the starting kit. Reproduce it locally on day one.

0.603D mAP @ IoU 0.5 · KITTI R40 · on 50 real frames
0.40realism of your synthetic frames

score = 0.60 · norm(mAP) + 0.40 · mean( norm CD, norm MMD, norm EMD, norm FPD )

CD
Chamfer. Symmetric nearest-neighbor cost. Rewards matching extent; punishes outliers.
MMD
Maximum Mean Discrepancy. Gaussian-kernel two-sample test. Rewards matching the density distribution.
EMD
Earth Mover's, exact Wasserstein-1. The strictest: match point count and density profile.
FPD
Frechet on 3-variate Gaussians. Matches the point cloud's centroid and spatial spread.
The key insight: every realism metric operates on raw geometry and density. They are all won by the same action that helps detection: replicate the real sensor and add realistic ray-drop. Detection and realism share one lever.
The winning formula

Priorities, highest leverage first

A real sequence, not a menu: earlier tiers unlock the later ones. Do Tier 1 before touching anything clever.

1

Digital twin + exact sensor and pose match

Reproduce the UrbanTwin recipe: a geospatial twin of the real site, a virtual LiDAR matched to the real beam pattern, and matched mounting height and tilt. Moves detection and all four realism metrics at once.

Impact: highEffort: high
2

Add the missing classes, especially pedestrians

The provided synthetic data has no pedestrians and folds vehicles loosely. On a class-averaged mAP a missing class is a hard zero. Generating credible pedestrians is likely the single biggest detection gain available.

Impact: highEffort: med
3

Ray-drop + density matching for the 40%

Turn "too clean" simulator output into sensor-realistic frames. Fit ray-drop to the real return statistics; match extent, point count, and radial and height density. Validate on a local realism proxy.

Impact: med-hiEffort: med
4

Robust detector + domain-generalization augmentation

Anchor-free voxel detector (CenterPoint or Voxel R-CNN), trained geometry-only, with Random Object Scaling, density resampling, and synthetic copy-paste for rare classes. Optionally a GBlobs position-invariant front-end for roadside viewpoints.

Impact: medEffort: med
5

Inference stack: TTA, ensemble, per-class thresholds

The repeatable challenge-winning pattern. Test-time augmentation, a multi-seed and multi-architecture ensemble fused with weighted box fusion, and per-class score tuning. Several mAP points for near-zero risk.

Impact: medEffort: low

Why synthetic fails on real

The Sim2Real gap, by cause

Relative leverage of each gap source for roadside LiDAR. Nearly every recommendation in the plans maps to closing one of these rows.

Point density / beam patternhigh-to-low density is the hard direction
Object size priorsthe box head memorizes sim sizes
Mounting height / tilt / viewpointroadside oblique geometry
Missing pointsocclusion, low reflectance, range
Intensity / reflectance realismCARLA uses a crude distance falloff
Scene content / traffic layoutobject placement distribution

Do

  • Match the exact sensor and pose
  • Set object sizes to real statistics
  • Add ray-drop and realistic sparsity
  • Train geometry-only for robustness

Avoid

  • Broad domain randomization (hurts realism)
  • Adding weather the real frames lack
  • Collapsing frame diversity to chase one metric
  • Heavy transformers that memorize sim patterns

Steal

  • UrbanTwin's digital-twin pipeline
  • ST3D's Random Object Scaling
  • DTS beam resampling augmentation
  • LiDARsim's learned ray-drop

The working stack

Tools worth standardizing on

Generate and refine

CARLA
Primary generator; matches the UrbanTwin recipe; labels from the actor graph.
UrbanTwin data
Provided UT-LUMPI / UT-V2X-Real-IC on Harvard Dataverse; train and submit day one.
LiGuard
Organizers' MIT pipeline; reads CARLA and KITTI; background filtering and clustering.
R2DM / DRUM
Range-image diffusion for optional ray-drop and reflectance refinement of sim output.

Train and evaluate

bdasl-gpu-server
8x RTX A6000 (48 GB): generate on 2 GPUs while training the rest with DDP; run both tracks in parallel.
OpenPCDet
Primary trainer; SECOND, PointPillars, CenterPoint, Voxel R-CNN, DSVT; native KITTI R40 eval.
spconv
Sparse-conv backend; install the CUDA-matched wheel.
Open3D
Point-cloud I/O and ICP registration for LUMPI's multiple LiDARs.
PyTorch3D + geomloss
Build the local realism scorer (Chamfer, EMD, MMD, FPD).

What is locked down, and the last details to read

Confirmed from CodaBench + papers

  • Domain generalization only: the detector trains on synthetic alone, no real data even unlabeled.
  • Realism is xyz geometry only (FPD is a 3-variate Gaussian); intensity does not affect the 40%.
  • LUMPI rig is five LiDARs: Hesai Pandar64, Velodyne HDL-64E, Hesai PandarQT, 2x Velodyne VLP-16.
  • Tracks 16684 (LUMPI) and 16685 (V2X-Real); LOI registered; not entering the ECCV instance.
